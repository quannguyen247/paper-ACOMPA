\vspace{0.75em}

We thank the reviewer for the careful assessment and for recognizing the paper's practical treatment of post-quantum cryptography (PQC) migration in heterogeneous Internet of Things (IoT) systems. We agree that the submitted figures were not suitable for publication. We replaced the four submitted figures with two author-redrawn vector schematics. Their SVG sources are included with the manuscript, and LaTeX uses cropped vector-PDF versions. The title and author list are unchanged, as are all reported benchmark values and the central placement conclusion. The revision also narrows the deployment claims to the evidence from the QEMU experiments, clarifies node and gateway responsibilities, removes the draft's unevaluated DMA and design-for-test details, and updates the supporting references.

\section*{Response to the overall assessment}

\textcolor{reviewblue}{\textbf{Reviewer assessment:}} \emph{Borderline Accept. The paper's core strength lies in its practical, architecture-driven approach to migrating heterogeneous IoT ecosystems to PQC. The study introduces a strategic algorithm-placement model across device tiers.}

\textbf{Response.} Section III-A now states the node, gateway, and server responsibilities as an explicit tiered placement model. Table I gives the placement and rationale for ML-KEM, ML-DSA, SLH-DSA, and hybrid mode. The Introduction uses the same framing, and the Conclusion limits the deployment claim to the node/gateway workflow measured in the prototype.

\section*{Response to the figure-quality comment}

\textcolor{reviewblue}{\textbf{Reviewer comment:}} \emph{I am mainly concerned about the AI-generated figures (Fig. 1 and Fig. 4). The human-generated figures (Fig. 2 and Fig. 3) are of low quality and therefore must be improved.}

\textbf{Response.} We agree. None of the four submitted image files is used in the revised manuscript. We redrew and consolidated the overview, hardware, sequence, and deployment views into two vector schematics. Both figures consist of vector paths and contain no embedded raster images. They use consistent line weights, typography, arrow directions, component boundaries, and captions.

The two figures divide the content as follows:

\begin{itemize}
  \item \textbf{Fig. 1, ``End-node architecture for PQC-enabled IoT devices,''} shows the processing core, PQC software stack, bootloader and secure boot, RAM, storage, network path, system bus, and peripheral interfaces discussed in Section III-C.
  \item \textbf{Fig. 2, ``Three-tier deployment map for quantum-safe session establishment and passkey authentication,''} shows constrained and Linux-capable end nodes, gateway-side ML-KEM/KDF/AEAD and signature functions, optional direct PQC operation, and cloud/server trust services discussed in Section III-D.
\end{itemize}

The sequence previously shown in submitted Fig. 3 is now described in Section III-D. The revised Fig. 2 combines the tier-placement content that was previously split between the overview and deployment figures. The manuscript contains exactly two figures and has no obsolete references to Figs. 3 or 4. The accompanying text clarifies placement conditions, credential ownership, gateway delegation, and failure handling. The reported benchmark values are unchanged, while the deployment claims have been narrowed to what the QEMU prototype supports.

\section*{Response to technical quality and soundness}

\textcolor{reviewblue}{\textbf{Reviewer assessment:}} \emph{Fair (Some technical issues or missing baselines, but potentially fixable).}

\textbf{Response.} We did not have a matched physical-board or accelerator baseline for this revision and therefore did not add an unmeasured comparison. Section IV now identifies the reported values as software measurements from a QEMU prototype, used as evidence for placement decisions rather than as cycle-accurate hardware results. Section IV-C states that Linux/QEMU resident-set size is not an estimate of ESP32 SRAM use. The limitations paragraph assigns physical-board power, radio throughput, flash wear, timing leakage, and comparison with existing PQC IoT architectures to future work.

Table I connects each primitive to a deployment tier and explains the placement. Table II reports elapsed time, resident memory, payload size, and the recommended tier; its measured values are unchanged. Section IV-D relates those measurements to buffer sizing, gateway admission control, and possible acceleration kernels. The end-node description identifies AXI, AHB, and APB as interfaces of the memory-mapped system bus. It replaces the draft's DMA-specific data path with a platform-neutral shared-buffer model because the evaluation did not measure a DMA implementation. The secure-channel text names AES-GCM and ChaCha20-Poly1305 as example authenticated-encryption schemes. We also removed the draft's design-for-test and fault-injection extension because it was outside the implemented and measured system.

\section*{Response to originality and novelty}

\textcolor{reviewblue}{\textbf{Reviewer assessment:}} \emph{Fair (Incremental improvement or a minor new application).}

\textbf{Response.} The paper does not claim a new cryptographic primitive. The revised Introduction defines the contribution as a layered node/gateway/server architecture, a PQC-aware passkey metadata and hybrid-policy model, and a measurement-based rule for placing ML-KEM, ML-DSA, and SLH-DSA. Section III and the two revised figures follow these system-level contributions. The standardized algorithms and reference software remain the basis of the prototype.
